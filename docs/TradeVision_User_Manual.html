Part A — Before You Start

A.1 What TradeVision is

TradeVision is an Indian-equity (NSE/BSE) decision-support and paper-trading platform. It ingests market data and trading-view alerts, builds a deterministic intelligence packet per symbol, evaluates 8 deterministic trading rules, pushes every firing through an auditable fail-closed risk gate, and — only when you explicitly enable it — simulates fills through a paper broker. It also runs nightly per-symbol backtests and ranks strategies by demonstrated per-stock evidence.

Design fact worth repeating: by default the system acts on nothing. Rule firing, execution and pattern analysis are all off until an operator turns them on. On a fresh install you will see an empty, quiet system until you complete Part E.

docker exec -it infra-backend-1 python manage.py createsuperuser docker exec infra-backend-1 python manage.py ensure_default_account # ensures a default trading account exists for the owner
The nightly backtest job requires a Django user named exactly admin. Create one:
docker exec infra-backend-1 python manage.py create_user admin --email admin@local --password <pw> --role owner
(Use the actual helper exposed by your install; otherwise createsuperuser with username admin.)

B.5 Health check after boot

  1. Open http://localhost:5173 (dev) — you should see the TradeVision login screen.
  2. The top-bar live dot must be green (connected).
  3. Open /pipeline-health — stages should show Healthy once data flows.
  4. Run docker compose ps — all workers healthy, beat up.

Part D — Running Procedure of the Architecture

D.1 Component map

[TradingView / Chartink webhooks]──┐ [Market-data poller (Beat 60s)]──┤──▶ Postgres (source of truth) │ │ Redis ◀─┘ (broker + event streams) │ Celery workers (market/ai/default) + Beat │ Backend API (Django ASGI :8000) │ Frontend (Vite :5173) ── user

D.2 The event pipeline (what runs, in order)

#StageTriggerOutput you can observe
1IngestionBeat poller (market hours) or webhooksRows in DB; Raw Ingestion Events page
2Technical analysisEach fresh candle (warm-up gated)technical_analysis.TechnicalAnalysisCompleted
3Intelligence packetTA completed handlerintelligence.PacketBuilt; regime + quality score
4Rule enginePacket built → 8 rules evaluatedrule_engine.RuleFired (if gate allows)
5Risk gateEach firing → 10 fail-closed checksRiskApproved / RiskRejected; Risk Decisions page
6ExecutionRiskApproved (only if execution enabled)Order → Fill; Orders/Positions/Trades pages
7ObservabilityEvery eventAudit log, Journal, dashboards, event streams

D.3 The event bus (reliability machinery)

  • Publish: durable DB row first → mirror to Redis stream (events:{type}, cap 10,000) → flag mirrored. A 30s beat re-mirrors any orphans, so Redis outages lose nothing.
  • Consume: a 2s beat drains consumer groups and dispatches handlers; per-(event, group) idempotency.
  • Retries: 5 attempts, backoff [1,5,30,120,600]s; acked only on terminal outcome; dead-letters are persisted and shown on Pipeline Health.
  • Reclaim: stale pending entries auto-reclaimed after 120s (crashed workers don't lose events).
  • Audit: a wildcard subscriber records every domain event append-only, reconstructable by correlation id.

D.5 Queues & workers (running procedure)

Tasks route by name to queues; workers consume explicit queue lists. If a queue has no worker, its tasks never run. Declared queues: webhooks, signals, analysis, ai_reasoning, decisions, execution, monitoring, portfolio, analytics, notifications, maintenance, market_data.

WorkerConsumesMissing queue symptoms
worker-marketmarket_data, processing, intelligence, rule_engineNo packets/rules
worker-aiaiNo recommendations
worker-defaultnotifications, analytics, default, maintenance, monitoring, webhooksNo nightly backtests, audit replay, health
Two routing caveats verified in source: rule-engine tasks route to rule_engine and monitor-broker-connection routes to default — confirm a worker actually consumes them, or these stages stay silent.

D.6 How to run a manual job

# Backtest one symbol for evidence (needs the 'admin' user) docker exec infra-backend-1 python manage.py per_symbol_backtests --symbols SBIN --days 730 # Backtest everything in the watchlist docker exec infra-backend-1 python manage.py per_symbol_backtests # Seed the default strategies/rules after a fresh migrate docker exec infra-backend-1 python manage.py seed_trading_defaults # Inspect DB quickly docker exec infra-postgres-1 psql -U tradevision -d tradevision_db -c "select count(*) from backtesting_backtestrun;"

Part E — User Workflow: Step-by-Step Procedure

This is the exact procedure a user follows to go from a fresh login to a running, evidence-ranked trading system.

Step 1 — Create your account and sign in. Open /login, choose “Create an account”, enter Full name, Email, Password. You land on the Dashboard. The top bar shows your role badge (owner/staff/viewer).
Step 2 — Set up the symbol watchlist (drives nightly backtests). Open /watchlist → “Add symbol” → type a ticker (e.g. SBIN) → Add. Set a group and optional price alerts (above/below). Add all stocks you care about. Expected: rows appear with last price/change; “Your watchlist is empty” disappears.
This watchlist feeds backtests only. To also get live signals you must add the same symbols to MARKET_DATA_POLL_WATCHLIST in infra/.env as NSE:SYMBOL,NSE:SYMBOL2 (equals EXCHANGE:SYMBOL) and restart the poller: docker compose -f … restart celery-beat celery-worker-market.
Step 3 — Generate per-stock evidence (nightly or manual). Either wait for the 03:00 IST job, or run now: docker exec infra-backend-1 python manage.py per_symbol_backtests --days 730. The runner skips completed combos and resumes interrupted ones. Expect each symbol to eventually show one run per ACTIVE strategy. Expected output: rows in /backtests with status → progress → Complete, then StrategySymbolAffinity rows appear for gate-clearing strategies.
Step 4 — Review the per-symbol rankings. Open /strategies → use the affinities panel filter to pick a symbol (e.g. SBIN). You will see which strategy earned rank 1 for that stock and its expectancy, profit factor, max drawdown and trade count. A stock with no passing strategy shows an empty table — that is correct (no fabricated evidence).
Step 5 — Create the automation rules you want. Open /rules → “New rule”. Configure: Name, Strategy, Symbols, Condition (Price/Volume/Indicator/News/Time), Comparison, Threshold, Action (Buy/Sell/Close/Alert/Hold), Sizing (fixed/% equity/% risk), Cooldown, max executions/day. Or use the pre-seeded rule configs from seed_trading_defaults and enable the specific (rule, regime) combinations you accept.
Rules created by backtesting start enabled=False. A GO verdict never flips a rule live — you must explicitly enable it.
Step 6 — Watch signals and recommendations. Open /signals (rule/model signals with Accept/Reject) and /strategies/recommendations (AI recommendations with Accept/Dismiss/Backtest). Accepting is how a signal becomes executable in downstream flows.
Step 7 — Decide whether to execute (paper). Set EXECUTION_ENGINE_ENABLED=True in infra/.env and restart the backend+default worker. Keep BROKER_ENVIRONMENT=sandbox and ALGO_REGISTRATION_ID="" for paper. Expected afterwards: RiskApproved decisions start producing Orders (CREATED→FILLED) on the Orders page; fills appear on Positions and Trades.
Step 8 — Monitor and stay safe. Daily: /pipeline-health (all stages Healthy), /risk/decisions (approvals/rejections & reasons), /reconciliation (broker vs ledger breaks), /audit (trail). Emergency: /kill-switch to halt everything or flatten positions.
Step 9 — Learn from outcomes. Optionally keep /journal entries, review Trader Memory (/memory) which records recommendations and their outcomes, and re-run backtests whenever you add a symbol.

E.1 What the nightly automation does for you

03:00 Beat → run_watchlist_per_symbol_backtests(days=730) → per_symbol_backtests (subprocess, isolated) → symbols = your Watchlist entries → for each symbol × ACTIVE strategy: skip if COMPLETED, else create isolated account + run → SymbolRankingService.rank_symbols() → StrategySymbolAffinity rows Automatically covers NEW watchlist symbols on the next tick.

F.2 Expected output of a backtest run

  • Status PENDING → RUNNING (progress bar) → COMPLETED (or FAILED with reason).
  • Result cards: Total Return %, Net P&L, Max Drawdown, Sharpe, Profit Factor, Trades, Win Rate, Avg Trade, final equity.
  • Drill-downs: trades table, per-symbol breakdown, parameters used.
  • Validation views: walk-forward OOS stats, edge-validation verdicts (Pass/Marginal/Fail), cost-sensitivity breakeven.
  • When 30+ trades, expectancy > 0, PF > 1.3 and maxDD < 20% are all met, the strategy earns a rank for that symbol.

F.3 Expected output a stock with no fires

Some rules legitimately never fire on certain stocks (e.g. Long Momentum on a given bank stock). You will see a COMPLETED backtest with 0 trades and no affinity row — that is correct behaviour, not a bug.

F.4 Edge-case outputs to recognise

You see…Meaning
MISSING_STOP_LOSS on Risk DecisionsThe firing had no stop for a rule that requires one — risk fails closed by design.
0 fills but orders createdPaper broker hasn't matched yet, or execution disabled so no orders at all.
Pipeline stage DownNo heartbeat within its silence budget — check that stage's worker/queue.
Dead-lettered handler on Pipeline HealthA handler failed 5×; look at the audit/event trace.
Backtest still RUNNING for a long timeLarge 730-day window; resume is cursor-based so safe to interrupt.

Part H — Operator Runbook & Safety

H.1 “Nothing is happening” — diagnostic order

  1. Empty MARKET_DATA_POLL_WATCHLIST? → the poller no-ops forever. Add symbols.
  2. Is it market hours (IST)? Outside market/pre-market the poller pauses.
  3. Provider = mock? → data is synthetic.
  4. Is a worker consuming the stage's queue?
  5. Do rules pass the gate? Check RuleConfig.enabled + validated_regimes[regime].status=="GO".
  6. EXECUTION_ENGINE_ENABLED=True? Otherwise no orders — by design.
  7. Check Pipeline Health, Journal, Audit for the trail.

H.2 Cold start checklist

  • ~60 candles per symbol before EMA/ATR/Supertrend rules fire (~1 trading day of 1-min bars). VWAP needs 09:15 IST opening candle.
  • Backtest evidence first, review affinities, then enable the specific rules you accept.

H.3 Safety posture

  • Live execution is triple-blocked: BROKER_ENVIRONMENT=live fails startup · ALGO_REGISTRATION_ID="" refuses live · paper bypass refuses when live. Paper is the only certified mode.
  • Risk is fail-closed: kill switches, concentration, freshness, capital, stops.
  • Kill Switch page = emergency stop + flatten positions.
